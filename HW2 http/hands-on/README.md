## سوال ۱: 

برای ایزوله‌سازی یک سرویس و جلوگیری از دسترسی مستقیم به آن از طریق اینترنت، از راهکارهای زیر استفاده می‌شود:

1. **محدودسازی آدرس اتصال (IP Binding):**
    سرویس‌ها به‌صورت پیش‌فرض معمولاً روی `0.0.0.0` (تمام اینترفیس‌های شبکه) گوش می‌دهند. برای محدودسازی، باید سرویس طوری پیکربندی شود که فقط روی لوپ‌بک (`127.0.0.1`) یا IP اختصاصی شبکه محلی (مانند `10.x.x.x` یا `192.168.x.x`) اجرا (`bind`) شود.

2. **اعمال قوانین فایروال (Firewall Rules / iptables / UFW):**
    مسدود کردن پورت سرویس روی رابط شبکه متصل به اینترنت (WAN) و اجازه دادن به ترافیک ورودی تنها از طریق رابط شبکه داخلی (LAN) یا منحصراً از سمت IP اختصاصی Reverse Proxy.

3. **شبکه‌های ایزوله کانتینری (Docker Private Network):**
    در محیط Docker، در صورتی که پورت کانتینر روی سیستم میزبان نگاشت (Publish) نشود (عدم استفاده از کلیدواژه `ports:` در داکر کامپوز) و کانتینر تنها عضو یک شبکه Bridge خصوصی مشترک با پروکسی باشد، هیچ کلاینتی خارج از آن شبکه به سرویس دسترسی نخواهد داشت.

4. **جداسازی در لایه شبکه (VLAN / Private Subnet):**
    در معماری‌های ابری (مانند VPC) یا مراکز داده سازمانی، قرار دادن سرور در ساب‌نت خصوصی (Private Subnet) بدون اختصاص IP عمومی و بدون مسیر خروجی مستقیم به Internet Gateway.

## سوال ۲: 

رویکرد **TLS Termination** به این معناست که ارتباط امن و رمزنگاری‌شده HTTPS کلاینت در لبه شبکه و روی سرور پروکسی پایان یافته و رمزگشایی می‌شود؛ سپس ترافیک به صورت رمزنشده (Plain HTTP) در بستر امن شبکه داخلی به سمت سرویس اصلی (Legacy) ارسال می‌گردد. اهداف و فلسفه این کار عبارتند از:

1. **پشتیبانی از سرویس‌های قدیمی (Legacy Compatibility):**
    سرویس‌های قدیمی معمولاً قابلیت پیاده‌سازی TLS مدرن را ندارند یا از نسخه‌های آسیب‌پذیر (مثل SSLv3 یا TLS 1.0) استفاده می‌کنند. پروکسی مدرن این امکان را می‌دهد که بدون دست‌کاری کدهای قدیمی، استانداردهای جدید امنیتی (مانند TLS 1.3) برای کلاینت‌ها فراهم شود.

2. **برداشتن بار پردازشی از سرور اصلی (Resource Offloading):**
    عملیات برقراری ارتباط امن (TLS Handshake) و محاسبات رمزنگاری و رمزگشایی برای پردازنده سنگین است. سپردن این مسئولیت به پروکسی، توان پردازشی سرویس داخلی را صرفاً برای اجرای منطق برنامه (Business Logic) آزاد می‌گذارد.

3. **مدیریت متمرکز گواهی‌های امنیتی (Centralized Certificate Management):**
    تمدید، اعتبارسنجی و نگهداری گواهی‌های SSL (مثلاً از طریق Let's Encrypt) تنها در یک نقطه واحد (پروکسی) انجام می‌شود و نیاز به اعمال تنظیمات روی تک‌تک سرویس‌های مستقل را از بین می‌برد.

4. **امکان بازرسی و پالایش بسته‌ها (Deep Packet Inspection & Security):**
    برای این‌که پروکسی‌ها و سامانه‌های امنیتی (مانند WAF) بتوانند هدرهای HTTP (نظیر هدر JWT)، پارامترهای درخواست و بدنه داده‌ها را بررسی، فیلتر یا لاگ کنند، نیاز دارند که ترافیک ابتدا رمزگشایی شود.
